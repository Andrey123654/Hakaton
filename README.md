# Обнаружение фишинговых URL по адресу

**Практическая работа 4 — хакатон на платформе Cyberhackai**
(дисциплина «Применение ML в кибербезопасности»)

Итоговый результат: **публичный F1 = 0.996062**, кросс-валидация (OOF) **F1 = 0.99195**
на 63 900 размеченных URL, **3-е место** в турнире.

Репозиторий содержит исходный код решения, тетрадку для воспроизведения,
снимки внешних данных и описание окружения — то, что требуется регламентом
(этап 9) для проверки воспроизводимости призового результата.

---

## 1. Постановка задачи

| Файл | Содержимое |
|---|---|
| `artifacts/data/train.csv` | 64 000 размеченных URL (`url,result`; 1 — фишинг) |
| `artifacts/data/test.csv` | 16 000 URL без меток (порядок строк задаёт порядок ответов) |
| `artifacts/data/sample.csv` | образец формата ответа `Id,Predicted` |

Метрика соревнования — F1. Оценка: публичный рейтинг по 20 % теста,
приватный — по 80 %.

## 2. Идея решения

### 2.1. Две независимые линии моделей

Итоговая мета-модель объединяет предсказания **двух независимо разработанных
линий**, что даёт декоррелированные ошибки:

* **Линия A** — иерархические счётчики меток по домену и пути (с исключением
  проверочных фолдов при обучении), ресурсные и словарные признаки, бустинги
  LightGBM, XGBoost, CatBoost.
* **Линия B** (`src/`) — лексико-структурные признаки URL (123), признаки
  HTML-контента страницы (76: формы, поля пароля, редиректы, обфускация,
  мимикрия под бренд), TF-IDF текста страницы и признаки «похожести на
  известные страницы»: top-K ближайших соседей по четырём представлениям
  (слова текста, разметка, шаблоны URL-путей, заголовки).

### 2.2. Сетевые признаки — ключевое дополнение

Набор собран в 2024 году, а фишинговые домены живут недолго: их блокируют по
жалобам, домены удаляют, хостинг отключают. Поэтому **текущее состояние домена**
сильно различает классы:

| Признак | Фишинг | Легитимные | AUC |
|---|---|---|---|
| Домен не резолвится | 62.9 % | 4.4 % | 0.792 |
| TLS-соединение не устанавливается | 75 % | 10 % | 0.821 |
| HTTP-запрос завершается ошибкой | 95.6 % | 46.3 % | 0.747 |
| Возраст домена (медиана) | 1 368 дней | 7 304 дня | 0.881 |
| Домен отсутствует в реестре RDAP | 50 % | 0 % | 0.735 |

Модули извлечения:

| Модуль | Что считает |
|---|---|
| `src/dns_features.py` | резолвинг A/AAAA, число адресов, MX и его провайдер, NS и парковщики доменов, TXT/SPF/DMARC, CNAME, коды ответа DNS |
| `src/tls_features.py` | доступность TLS, издатель, возраст и срок сертификата, число SAN, wildcard, самоподпись, отпечаток сертификата |
| `src/http_features.py` | код и класс ответа, редиректы, совпадение конечного хоста, апгрейд схемы, признаки парковки |
| `src/rdap_features.py` | возраст регистрации домена, срок до истечения, статусы EPP, регистратор, признак «нет в реестре» |
| `src/ip_features.py` | номер AS и провайдер, возраст выделения IP-префикса, страна, облако/резидентные сети |

### 2.3. Мета-модель

`HistGradientBoostingClassifier` (200 итераций, скорость обучения 0.10,
**4 листа**, L2 = 1) на:

* логитах предсказаний 7 базовых моделей (6 моделей линии A + единый стекинг
  линии B) — 7 столбцов;
* 67 сетевых признаках.

Мелкие деревья на 138 признаках устойчивее глубоких: более крупные
конфигурации давали на 0.0002–0.0005 меньший F1.

### 2.4. Достигнутые результаты

| Решение | OOF F1 | Публичный F1 |
|---|---|---|
| Базовая модель (URL + контент + текст) | 0.98606 | 0.991464 |
| Ранговое объединение поколений | 0.98899 | 0.994416 |
| Лучшая модель линии A (V10) | 0.99031 | 0.995404 |
| + сетевые признаки DNS/TLS/HTTP | 0.99162 | 0.995733 |
| **+ RDAP и IP/ASN (итоговое)** | **0.99195** | **0.996062** |

## 3. Воспроизведение результата

### 3.1. Быстрый путь: тетрадка (рекомендуется)

```bash
python -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/jupyter nbconvert --to notebook --execute --inplace \
    notebooks/best_solution_0.996062.ipynb
```

Тетрадка `notebooks/best_solution_0.996062.ipynb` использует только артефакты из
`artifacts/` (предсказания базовых моделей и снимки сетевых данных), поэтому
воспроизводится детерминированно, без обращений к сети. Ожидаемый результат:
**OOF F1 = 0.99194** и файл `submission_from_notebook.csv`.

Ноутбук воспроизводит конвейер на актуальных снимках; его ответ отличается от
загруженного `submission_net_full.csv` в 18 строках из 16 000, потому что снимок
RDAP был позже дополнен повторным опросом 896 доменов после троттлинга реестров.
Оценка качества при этом не меняется.

### 3.2. Полный путь: из исходных данных

```bash
# линия B: признаки контента, текста, соседей и обучение поколений (~5-6 часов)
CONTENT_DIR="/путь/к/Архив 3" bash run_all.sh

# сетевые признаки (нужен доступ в интернет, ~40 минут суммарно)
.venv/bin/python src/dns_features.py  --out cache/dns_all.pkl  --workers 192
.venv/bin/python src/tls_features.py  --out cache/tls_all.pkl  --workers 128
.venv/bin/python src/http_features.py --out cache/http_all.pkl --workers 128
.venv/bin/python src/rdap_features.py --out cache/rdap_all.pkl --workers 20
.venv/bin/python src/ip_features.py   --out cache/ip_asn.pkl   --workers 192

# линия A (каталоги improved_v1..v11, скрипты tools/improve_v*.py)
.venv/bin/python tools/improve_v1.py && .venv/bin/python tools/blend_improved_v1.py

# итоговая мета-модель
.venv/bin/python tools/eval_dns_gain.py --all-sources \
    --dns "cache/dns_a.pkl,cache/dns_rcode.pkl,cache/dns_all.pkl,cache/tls_all.pkl,cache/http_all.pkl:url,cache/rdap_all.pkl:domain,cache/ip_asn.pkl" \
    --model gbdt --no-neighbors --out submission_net_full.csv
```

## 6. Ограничения метода

* **Сетевые признаки временны́е.** Они описывают состояние домена на момент
  запроса, а не его содержимое. Внутри соревнования это корректно: обучающая и
  тестовая выборки собраны в один период, публичная и приватная части — случайные
  подмножества одного теста, правила разрешают сторонние данные. Для потоковой
  детекции «здесь и сейчас» признак не переносится — там домен атаки ещё жив.
  Поэтому снимки сохранены в репозитории, и результат воспроизводится из них
  детерминированно, без повторных запросов.
* **Остаточные ошибки упираются в шум разметки.** В обучающем наборе
  встречаются, например, `login.yahoo.com` с меткой «фишинг» и спам-домены в
  зонах `.dance`/`.webcam` с меткой «безопасный». Публичный рейтинг считается по
  3 200 адресам (стандартная ошибка оценки ≈ 0.00125), поэтому решения в группе
  0.9954–0.9961 статистически неразличимы.
