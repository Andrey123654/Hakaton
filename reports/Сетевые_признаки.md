# Сетевые признаки: DNS, TLS, HTTP

Документ описывает итерацию, которая дала наибольший прирост качества после
исчерпания текстовых и доменных признаков.

## Идея

Набор организаторов собран в 2024 году. Фишинговые ресурсы живут недолго: их
блокируют по жалобам, домены удаляют, хостинг отключают. Легитимные домены
продолжают работать. Значит, **текущее сетевое состояние домена** (резолвится
ли он, отвечает ли по HTTPS, что отдаёт по HTTP) несёт информацию о метке.

Проверка на стратифицированной выборке из 3000 обучающих адресов:

| Признак | Значение у фишинга | Значение у легитимных | AUC |
|---|---|---|---|
| Домен не резолвится | 62.9 % | 4.4 % | **0.792** |
| TLS-соединение не устанавливается | 75 % | 10 % | **0.821** |
| HTTP-запрос завершается ошибкой | 95.6 % | 46.3 % | **0.747** |
| HTTP отвечает 2xx | 4.3 % | 52.7 % | 0.743 |
| Код NXDOMAIN (домен удалён) | 25.2 % всех хостов | — | — |
| Возраст TLS-сертификата (медиана) | 72 дня | — | — |
| Возраст домена (медиана) | 1368 дней | 7304 дня | **0.881** |
| Домен отсутствует в реестре RDAP | 50 % | 0 % | **0.735** |
| Срок до истечения домена (медиана) | 149 дней | 509 дней | 0.830 |

## Что считается

`src/dns_features.py`:
резолвинг A/AAAA, число адресов, наличие IPv6, MX (и его провайдер: Google,
Microsoft, Яндекс), NS и их семейство (Cloudflare, парковщики доменов),
TXT, SPF, DMARC, CNAME, код ответа DNS (NXDOMAIN / таймаут / SERVFAIL).

`src/tls_features.py`: доступность TLS, версия протокола, издатель
(Let's Encrypt, бесплатные, платные УЦ), возраст сертификата и срок до
истечения, число SAN-имён, wildcard, совпадение CN с хостом, самоподпись.

`src/http_features.py`: код и класс ответа, факт редиректа, совпадение
конечного хоста с исходным, апгрейд схемы http→https, размер тела, наличие
заголовка Server, признаки парковки домена.

`src/rdap_features.py` (возраст домена): возраст регистрации, срок до
истечения, статусы EPP (clientHold, pendingDelete), регистратор, число NS,
а также признак «домен отсутствует в реестре» (404 — домен удалён).

`src/ip_features.py` (IP и автономная система): номер AS и его название,
возраст выделения IP-префикса, страна и регистратура, признаки облака/CDN
и резидентных сетей, факт отсутствия маршрута. Источник — bulk-сервис
Team Cymru, отдающий до тысячи адресов за один запрос.

## Результат

Мета-модель (градиентный бустинг, 300 итераций, 8 листьев) на логитах
предсказаний обеих линий решения и 49 сетевых признаках:

| Конфигурация | OOF F1 (63 900 объектов) |
|---|---|
| Лучшая модель проекта до этой итерации (V4 линии A) | 0.99041 |
| Логиты обеих линий без сетевых признаков | 0.99014 |
| Только сетевые признаки | 0.86763 |
| Логиты + DNS/TLS | 0.99137 |
| Логиты + DNS/TLS/HTTP | 0.99162 |
| Логиты + DNS/TLS/HTTP/RDAP/IP-ASN (67 признаков) | 0.99191 |
| То же после исправления разбора TLS-сертификатов | **0.99195** |

Прирост к лучшей модели проекта: **+0.00154 OOF** (≈ 98 исправленных ошибок
на 63 900 объектах).

## История отладки: невидимый TLS-признак

Первый прогон TLS-признаков давал `tls_ok = 1` для 32 143 хостов, но все
остальные колонки оставались пустыми. Причина: при `verify_mode = CERT_NONE`
метод `getpeercert()` возвращает пустой словарь, поэтому сертификат молча
не разбирался. После перехода на разбор DER (встроенный декодер CPython
через временный PEM-файл) сертификат читается у 90.6 % живых доменов.
Прирост от исправления оказался небольшим (+0.00004 OOF): возраст сертификата
коррелирует с возрастом домена, который уже учтён признаками RDAP.

Итоговая мета-модель — градиентный бустинг с очень мелкими деревьями
(200 итераций, скорость 0.10, 4 листа, L2 = 1): более простая модель
устойчивее на 138 признаках.

## Важная оговорка о природе признака

Признак **временной**: он отражает состояние доменов на момент запроса, а не
их содержимое. Внутри соревнования это корректно (обучающая и тестовая
выборки собраны в один период, публичная и приватная части — случайные
подмножества одного теста), и правила разрешают сторонние данные. Но такой
признак не переносится на потоковую детекцию «здесь и сейчас»: там домен
фишинга ещё жив. В отчёте это зафиксировано как ограничение метода.

## Воспроизводимость

Состояние доменов меняется во времени, поэтому запросы **нельзя повторять**
при воспроизведении. Снимки сохранены и поставляются вместе с кодом:

| Файл | Содержимое | Размер |
|---|---|---|
| `cache/dns_a.pkl` | A/AAAA-записи по 51 184 хостам | 1.5 МБ |
| `cache/dns_rcode.pkl` | коды ответа DNS | 1.2 МБ |
| `cache/dns_all.pkl` | MX/NS/TXT/DMARC/CNAME | 8.6 МБ |
| `cache/tls_all.pkl` | сертификаты 35 778 живых доменов | 2.5 МБ |
| `cache/http_all.pkl` | HTTP-состояние 79 848 URL | 13 МБ |
| `cache/rdap_all.pkl` | регистрация 34 314 доменов | 3.4 МБ |
| `cache/ip_asn.pkl` | ASN и префиксы 51 184 хостов | 2.5 МБ |

Дополнительно проверялись и отклонены как неэффективные: текущее содержимое
живых страниц (дублирует признак «домен жив»), архивные копии Wayback Machine
(слабый и противоречивый сигнал, AUC 0.62), сглаживание предсказаний внутри
домена (+0.00008 — в пределах шума), повторный опрос RDAP после троттлинга
(восстановлено 896 доменов, прироста нет).

Полный цикл:

```bash
# извлечение снимков (однократно, ~40 минут суммарно)
.venv/bin/python src/dns_features.py --out cache/dns_all.pkl
.venv/bin/python src/tls_features.py --out cache/tls_all.pkl
.venv/bin/python src/http_features.py --out cache/http_all.pkl

# мета-модель и файл ответов
.venv/bin/python src/rdap_features.py --out cache/rdap_all.pkl --workers 20
.venv/bin/python src/ip_features.py --out cache/ip_asn.pkl --workers 192

.venv/bin/python tools/eval_dns_gain.py --all-sources \
    --dns "cache/dns_a.pkl,cache/dns_rcode.pkl,cache/dns_all.pkl,cache/tls_all.pkl,\
cache/http_all.pkl:url,cache/rdap_all.pkl:domain,cache/ip_asn.pkl" \
    --model gbdt --no-neighbors --out submission_net_full.csv
```

При наличии сохранённых снимков результат воспроизводится детерминированно
(фиксированный `random_state`).

## Оценка подсказки задания о сторонних датасетах

В задании упомянуты корпуса SpamAssassin, LingSpam и SpamBase (UCI). Это
коллекции спам-писем, то есть источник того же класса, что и текст страниц:
словари «спамных» слов и фраз. Проверка показывает, что перенос здесь
избыточен: модели обеих линий уже обучаются на TF-IDF текста 63 900 реальных
страниц с метками именно этой задачи, что строго информативнее общих
почтовых словарей. Использование корпусов имело бы смысл при дефиците
размеченных данных или для задачи классификации писем; для URL-детекции
ожидаемый вклад лежит ниже уровня шума (OOF-различия порядка 0.0001).
